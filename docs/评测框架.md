# 评测框架

对照实验要回答的问题是：**同样的信息，组织成图还是摊平成文本，哪种更好用、好多少。**

这份文档确定问题集怎么分层、答案怎么判、差异怎么算，以及哪些结论在样本量下站不住。

---

## 一、四条链路

同名同源，区别只在数据怎么组织、怎么取。

| 编号 | 链路 | 做法 |
|---|---|---|
| ① | 文档模式（top-k） | 源数据渲染成文本 → 分块 → bge-m3 嵌入 → 向量检索 5 块 → 大模型读片段回答 |
| ①' | 文档模式（全语料） | 不做检索，把全部语料塞进上下文 |
| ② | 朴素实现 | 同一个模型，不加 few-shot、不加校验、不加自修复 |
| ③ | 倒置LLM 增强版 | schema + 方向提示 + few-shot → 四道静态校验 → EXPLAIN → 只读执行 → 自修复（≤2 轮） |

**两组对比回答两个不同的问题：**

```
① vs ③    同样的信息，扁平文本 vs 图结构，差多少
② vs ③    同样的图和模型，加不加工程化，差多少
```

### ①' 这条为什么要加

它把「信息完整性」这个变量彻底消掉。

我们的语料约 19,800 token，**装得进上下文**。所以 ①' 拿到的是全部信息，一份不少。

如果在图计算类问题上 ①' 仍然答不对，那就直接证明：**瓶颈是算不出来，不是看不到。**

这比「因为语料太大装不下所以传统 RAG 输」有力得多——后者可以归结为工程限制，前者是原理限制。

## 二、问题集分层

实际生成 153 道，比计划的 160 少 7 道 —— 见下面的说明。

| 层 | 计划 | 实际 | 例题 |
|---|---|---|---|
| A 类 事实查找 | 40 | **34** | tenlong-001 属于哪个车间？ |
| B1 多跳依赖 | 25 | 25 | huanmai-002 停机会影响哪些设备？ |
| B2 聚合统计 | 25 | 25 | chengxin-006 一共检修过几次？ |
| B3 否定与补集 | 20 | **19** | 哪些设备还有未完成的检修？ |
| B4 排序与阈值 | 20 | 20 | 哪些备件库存最少的 3 个？ |
| B5 根因追溯 | 20 | 20 | 主轴轴承磨损会导致哪些故障？ |
| 拒答 | 10 | 10 | 3 号泵的检修周期是多久？ |
| **合计** | 160 | **153** | |

**两处没凑够，都不打算硬凑：**

- A 类少 6 道：有些设备在台账里没有车间字段，生成了也没答案，自动跳过
- B3 少 1 道：补集题分两层生成（全局补集 + 按型号限定），**空集答案的题自动丢弃** ——
  「哪些备件库存低于安全线」这种返回空的题目测不出东西，数据里所有备件都合规

多出来的题如果都是同模板实例，信息量很低。宁可少几道。

**A 类的作用是证明没作弊。** 事实题上传统 RAG 大概率打平甚至更好——这是预期结论，不是失败。有了它，B 类上的优势才说明问题。

**拒答题的作用是测幻觉。** 问题和答案都不在知识库里，两边都该明确说"查不到"。谁编出答案来，谁就扣分。

### 题量怎么定的

配对设计的功效取决于**不一致对的数量**，不是总题量。近似式：

```
n ≈ 7.84 × (π_d − d²) / d²
```

π_d 取 0.3（两边判断不一致的比例）：

| 想检出的差距 | 需要题量 |
|---|---|
| 20 个百分点 | 约 50 道 |
| 15 个百分点 | 约 100 道 |
| **12 个百分点** | **约 160 道** |
| 10 个百分点 | 约 230 道 |

取 160，是「即使差距只有 12 个百分点也能检出」的配置。上限受数据限制：这份档案能出的不重复题目约 200–250 道。

**π_d 越大功效越高。** 如果 B 类上传统 RAG 大面积答错、倒置LLM 大面积答对，π_d 会接近 1，那时 60 道就够。所以先跑一轮看实际差距，再决定要不要扩。

## 三、判定方式

**能确定性判定的，绝不用 LLM。**

| 答案形态 | 判法 | 用 judge 吗 |
|---|---|---|
| 集合（设备名、备件名） | 集合 F1 | 否 |
| 数值（次数、间隔、余量） | 数值比对，带容差 | 否 |
| 有序列表（Top-N） | Top-N 集合 F1 | 否 |
| 路径（故障链） | 路径节点序比对 | 否 |
| 开放描述 | LLM judge | 是 |
| **从散文答案里抽字段** | LLM 抽取 | 是 |

### 字段级准确率

把两边的答案都抽成结构化字段，逐个比对。比如「哪些设备还有未完成的检修」：

```
标准答案   {设备: [chengxin-048, chengxin-049, chengxin-050, ...]}   8 项
倒置LLM    {设备: [chengxin-048, chengxin-049, chengxin-050, ...]}   8 项 → 命中 8/8
文档模式   "根据资料，chengxin-048 和 chengxin-049 的检修尚未完成"    → 命中 2/8
```

比整句比对的好处：**能看出错在哪一项**，而不是一个笼统的对错。而且方向、数值这类字段可以确定性判定，不受语义漂移影响。

### 抽取的公平性

文档模式输出散文，抽成字段要靠 LLM。这个抽取本身会出错，那测出来的就不只是「架构差异」，还掺了「抽取难度」。

处理方式三条：

1. **两边用同一个抽取 prompt、同一个模型** —— 保持对称
2. **抽不出来的算错，但单独统计「抽取失败」的比例**，让人看得出这部分噪声有多大
3. 有实证显示 embedding 会混淆反义词（"increasing" 和 "decreasing" 的余弦相似度能到 0.74），所以方向性字段用同义词表比对，不用语义相似度

## 四、统计

### 用什么检验

配对设计，逐题对错可判，所以：

- **McNemar 检验**（二元结果）
- **paired bootstrap**（连续指标，如 F1）
- 都报 95% 置信区间

### 分层之后不做显著性声称

每层只有 20–40 道。这个规模下每层能检出的差距在 25 个百分点以上，功效太低。

**所以分层结果只报准确率加置信区间，不标"显著"。** 显著性只在整体（160 道）和 A/B 大类上做。

### 被判据的诚实声明

- 配对不同对的数量决定功效。不一致对只有 10–30 时，可能藏着好几个百分点的效应
- **不显著不等于没用**
- 二项分布下，两个比例差 10 个百分点、每组 100 样本，p 值约 0.05——这是临界规模

## 五、标准答案从哪来

**这是整个评测可信度的上限。** 答案生成链每一环都由 AI 完成，不是领域专家：

```
源文件 → 规范化 → 归一 → 建图 → 手写参考 Cypher → 标准答案
  合作方      AI       AI     AI          AI              AI
```

所以「怎么保证 AI 造的答案是对的」这个问题必须正面回答。

### 原则：AI 判断的地方，必须配一个不依赖 AI 的验证手段

「不造假」是无法证明的承诺，**「可验证」才是可操作的**。按这条原则过一遍管线：

| AI 在哪判断 | 验证手段 | 状态 |
|---|---|---|
| 规范化（编号展开、分隔符、通用后缀） | 规则 + 台数校验 | 全规则 |
| 归一：因果 | 规则直接抽 | 全规则 |
| 归一：同义 | 高置信规则 + 低置信人工 | 有队列 |
| 归一：同名包含 | 模型判 + 人工 | 全靠人工 |
| **语义理解**（「影响」是上游还是下游） | **无** | **缺口** |

### 实测：模型真的会造

任务里出过一条边：`卡盘松动 → 工件尺寸超差`。查回手册发现：

```
「主轴异响」那一行的成因列 = 主轴轴承磨损或缺油，或卡盘松动
「工件尺寸超差」那一行的成因列 = 刀具磨损或丝杠反向间隙过大
```

`卡盘松动` 是**主轴异响**那一行的成因，跟工件尺寸超差没有关系。那条边是模型自己推的。

**危险的地方在于它看起来合理** —— 卡盘松了确实可能影响尺寸精度。人工审也容易放过。

**修法：把「模型判断」换成「规则直抽」。** 手册每行的结构是「现象 | 成因 | 处理」，
成因和现象的对应关系文档已经写死，模型插一脚只会引入错误。改完之后 47 条因果全部来自
手册原文，AI 判断 **0 次**。

### 硬约束：出题的 AI 不能是被测的 AI

上面那条边的成因是 `qwen2.5-coder:14b` 判的，而倒置LLM 也用它。
**测的是「模型能不能猜对另一个模型的判断」，循环论证。**

出题和被测必须分开。现在因果改成规则后这一条不犯了，但归一的候选仍然是同一个模型出的，
那一层参与了图谱构建 —— 这条要在报告里标注出来。

### 三种核对抓的东西不一样

```
① 一致性核对   查库 vs 独立路径重算     → 抓「实现错误」
② 合理性核对   人看结果合不合物理常识   → 抓「语义错误」
③ 源文件核对   人看原文档怎么说的       → 抓「数据理解错误」
```

**只做 ①是不够的**：如果建图逻辑有错，图和参考查询共享同一个错误假设，两边自洽地错。
依赖边方向就错过一次：数量 650 对、对账全过、方向全反。

**只做 ②也不够**：审的人不知道焊接后面接磨削，就看不出 22 台下游对不对。

所以出题时给每题标注**答案离原始数据有多远**（`derivation` 字段），审阅清单按这个排序：

| 层级 | 题量 | 含义 | 需要人核 |
|---|---|---|---|
| `interpreted` | 20 | 依赖把一段自由文本解释成因果或措施 | **最需要** |
| `relational` | 45 | 依赖定义的路径语义 | **需要** |
| `negation` | 19 | 集合相减 | 扫过 |
| `aggregate` | 25 | 数多条记录 | 扫过 |
| `direct` | 44 | 从一条记录直接读 | 扫过 |

**剩下的缺口是语义理解层**。「停机影响谁 = 找下游」是一条规则、独立路径、AI 全都遵守的
假设，没有任何自动路径能验证这个假设本身。唯一手段是懂机床的人看那 65 道题。

## 六、已知陷阱

### 排序题的答案可能并列

实测撞到过：「哪个故障模式出现次数最多」有四条并列 29 次，「哪台设备被其他设备依赖最多」有六条并列 16 次。

**出题时用独立路径重算一遍，问题比预想的严重得多：**

```
检修次数最多的前 3 台设备     第 3 名分值 5，    33 台并列
被最多设备依赖的前 5 台设备   第 5 名分值 21，    4 台并列
被最多设备依赖的前 10 台设备  第 10 名分值 16，   8 台并列
```

**33 台设备并列 5 次**——「前 3 台」根本没有唯一答案，按唯一答案判分，模型答对了也会被判错。

**判定方式：不比正确答案集合，比分值门槛。**

```
标准答案 = 图算的前 k 个 → 取出第 k 名的分值作为阈值
模型答案 = 模型给的 k 个
判对的条件：模型这 k 项的分值全部 ≥ 阈值，且数量对
```

这样并列不影响判定。模型挑了并列区里的任意 k 个都算对，只要分值够。

**为什么不用「改成阈值问法」**：问「检修次数达到 5 次的设备有哪些」答案唯一、判分简单，但「前几名」是人真实的问法，改掉就偏离了实际场景。判定层解决更好。

**这条也是「出题要独立验证」的直接收益**：不重算一遍，根本发现不了并列有 33 台这么多。

### 测试集不能复用 bench 题

`data/bench_questions.json` 那 12 条已经被 few-shot 示例污染过——示例是看着它们的失败样本调出来的。拿它们测，测的是"示例背得熟不熟"。

**正式评测的问题集必须另出。**

### 问题措辞要跟数据语义对齐

「哪些设备从未检修过」返回 0 行，不是系统错——数据里每台设备都有工单，那 8 台只是没完成。改成「哪些设备还有未完成的检修」才对。

出题时要核对：**问的东西在数据里真的存在吗。**

### 「能执行率」不能当主指标

公开基准上 GPT-4o 生成的 Cypher 语法可执行率 94.93%，真实执行准确率 60.18%，相差约 35 个百分点。

只报执行成功率的评测没有意义。

## 七、判分流程

```
① 出题          从图谱自动生成候选，人工审一遍
② 标注          每条题给出标准答案，写成结构化字段
③ 跑            四条链路各跑一遍，记录答案、耗时、trace
④ 抽取          文档模式的散文答案抽成字段（同一 prompt）
⑤ 判定          字段比对（确定性）+ LLM judge（开放题）
⑥ 校准          人工盲抽 20–30 条，报 judge 与人的一致率
⑦ 统计          分层准确率 + 配对检验 + 置信区间
⑧ 报告          出 HTML，同时给 CSV 明细供复核
```

第 ⑥ 步不能省。LLM judge 是**会出错的测量仪器**，不是中立法官——有已知的位置偏差、长度偏差、自我偏好。人工抽检是唯一能校准它的手段。

---

## 八、出题的分工

问题集自动生成候选（每个设备、每个故障模式、每条流程套模板），然后**人工审一遍**。

审的重点三条：

1. **答案唯一吗** —— 会不会并列
2. **答案在数据里吗** —— 问的东西真的存在吗
3. **措辞有歧义吗** —— 两种合理解读会不会导致不同答案

自动生成能出量，但审不出这三条的话，测出来的准确率反映的是题目的质量而不是系统的质量。
