# 评测框架

对照实验要回答的问题是：**同样的信息，组织成图还是摊平成文本，哪种更好用、好多少。**

这份文档确定问题集怎么分层、答案怎么判、差异怎么算，以及哪些结论在样本量下站不住。

---

## 一、四条链路

同名同源，区别只在数据怎么组织、怎么取。

| 编号 | 链路 | 做法 |
|---|---|---|
| ① | 文档模式（top-k） | 源数据渲染成文本 → 分块 → bge-m3 嵌入 → 向量检索 5 块 → 大模型读片段回答 |
| ①' | 文档模式（全语料） | 不做检索，把全部语料塞进上下文 |
| ② | 朴素实现 | 同一个模型，不加 few-shot、不加校验、不加自修复 |
| ③ | 倒置LLM 增强版 | schema + 方向提示 + few-shot → 四道静态校验 → EXPLAIN → 只读执行 → 自修复（≤2 轮） |

**两组对比回答两个不同的问题：**

```
① vs ③    同样的信息，扁平文本 vs 图结构，差多少
② vs ③    同样的图和模型，加不加工程化，差多少
```

### ①' 这条为什么要加

它把「信息完整性」这个变量彻底消掉。

我们的语料约 19,800 token，**装得进上下文**。所以 ①' 拿到的是全部信息，一份不少。

如果在图计算类问题上 ①' 仍然答不对，那就直接证明：**瓶颈是算不出来，不是看不到。**

这比「因为语料太大装不下所以传统 RAG 输」有力得多——后者可以归结为工程限制，前者是原理限制。

## 二、问题集分层

160 道，按题型分七层。

| 层 | 题量 | 例题 | 判据 |
|---|---|---|---|
| A 类 事实查找 | 40 | tenlong-001 属于哪个车间？ | 判据的"能答对"侧 |
| B1 多跳依赖 | 25 | huanmai-002 停机会影响哪些设备？ | 关键词"变长路径" |
| B2 聚合统计 | 25 | chengxin-006 一共检修过几次？ | "遍历算数" |
| B3 否定与补集 | 20 | 哪些设备还有未完成的检修？ | "补集" |
| B4 排序与阈值 | 20 | 哪些备件库存最紧张？ | "拓扑排序" |
| B5 根因追溯 | 20 | 主轴轴承磨损会导致哪些故障？ | "路径" |
| 拒答 | 10 | 3 号泵的检修周期是多久？ | 知识库没有，该说不知道 |

**A 类的作用是证明没作弊。** 40 道事实题上传统 RAG 大概率打平甚至更好——这是预期结论，不是失败。有了它，B 类上的优势才说明问题。

**拒答题的作用是测幻觉。** 问题和答案都不在知识库里，两边都该明确说"查不到"。谁编出答案来，谁就扣分。

### 题量怎么定的

配对设计的功效取决于**不一致对的数量**，不是总题量。近似式：

```
n ≈ 7.84 × (π_d − d²) / d²
```

π_d 取 0.3（两边判断不一致的比例）：

| 想检出的差距 | 需要题量 |
|---|---|
| 20 个百分点 | 约 50 道 |
| 15 个百分点 | 约 100 道 |
| **12 个百分点** | **约 160 道** |
| 10 个百分点 | 约 230 道 |

取 160，是「即使差距只有 12 个百分点也能检出」的配置。上限受数据限制：这份档案能出的不重复题目约 200–250 道。

**π_d 越大功效越高。** 如果 B 类上传统 RAG 大面积答错、倒置LLM 大面积答对，π_d 会接近 1，那时 60 道就够。所以先跑一轮看实际差距，再决定要不要扩。

## 三、判定方式

**能确定性判定的，绝不用 LLM。**

| 答案形态 | 判法 | 用 judge 吗 |
|---|---|---|
| 集合（设备名、备件名） | 集合 F1 | 否 |
| 数值（次数、间隔、余量） | 数值比对，带容差 | 否 |
| 有序列表（Top-N） | Top-N 集合 F1 | 否 |
| 路径（故障链） | 路径节点序比对 | 否 |
| 开放描述 | LLM judge | 是 |
| **从散文答案里抽字段** | LLM 抽取 | 是 |

### 字段级准确率

把两边的答案都抽成结构化字段，逐个比对。比如「哪些设备还有未完成的检修」：

```
标准答案   {设备: [chengxin-048, chengxin-049, chengxin-050, ...]}   8 项
倒置LLM    {设备: [chengxin-048, chengxin-049, chengxin-050, ...]}   8 项 → 命中 8/8
文档模式   "根据资料，chengxin-048 和 chengxin-049 的检修尚未完成"    → 命中 2/8
```

比整句比对的好处：**能看出错在哪一项**，而不是一个笼统的对错。而且方向、数值这类字段可以确定性判定，不受语义漂移影响。

### 抽取的公平性

文档模式输出散文，抽成字段要靠 LLM。这个抽取本身会出错，那测出来的就不只是「架构差异」，还掺了「抽取难度」。

处理方式三条：

1. **两边用同一个抽取 prompt、同一个模型** —— 保持对称
2. **抽不出来的算错，但单独统计「抽取失败」的比例**，让人看得出这部分噪声有多大
3. 有实证显示 embedding 会混淆反义词（"increasing" 和 "decreasing" 的余弦相似度能到 0.74），所以方向性字段用同义词表比对，不用语义相似度

## 四、统计

### 用什么检验

配对设计，逐题对错可判，所以：

- **McNemar 检验**（二元结果）
- **paired bootstrap**（连续指标，如 F1）
- 都报 95% 置信区间

### 分层之后不做显著性声称

每层只有 20–40 道。这个规模下每层能检出的差距在 25 个百分点以上，功效太低。

**所以分层结果只报准确率加置信区间，不标"显著"。** 显著性只在整体（160 道）和 A/B 大类上做。

### 被判据的诚实声明

- 配对不同对的数量决定功效。不一致对只有 10–30 时，可能藏着好几个百分点的效应
- **不显著不等于没用**
- 二项分布下，两个比例差 10 个百分点、每组 100 样本，p 值约 0.05——这是临界规模

## 五、已知陷阱

### 排序题的答案可能并列

实测撞到过：「哪个故障模式出现次数最多」有四条并列 29 次，「哪台设备被其他设备依赖最多」有六条并列 16 次。

按"唯一标准答案"判，模型答对了也会被判错。

**对策**：排序题的 ground truth 写成**集合**，或者题目直接要求返回 Top-N。

### 测试集不能复用 bench 题

`data/bench_questions.json` 那 12 条已经被 few-shot 示例污染过——示例是看着它们的失败样本调出来的。拿它们测，测的是"示例背得熟不熟"。

**正式评测的问题集必须另出。**

### 问题措辞要跟数据语义对齐

「哪些设备从未检修过」返回 0 行，不是系统错——数据里每台设备都有工单，那 8 台只是没完成。改成「哪些设备还有未完成的检修」才对。

出题时要核对：**问的东西在数据里真的存在吗。**

### 「能执行率」不能当主指标

公开基准上 GPT-4o 生成的 Cypher 语法可执行率 94.93%，真实执行准确率 60.18%，相差约 35 个百分点。

只报执行成功率的评测没有意义。

## 六、判分流程

```
① 出题          从图谱自动生成候选，人工审一遍
② 标注          每条题给出标准答案，写成结构化字段
③ 跑            四条链路各跑一遍，记录答案、耗时、trace
④ 抽取          文档模式的散文答案抽成字段（同一 prompt）
⑤ 判定          字段比对（确定性）+ LLM judge（开放题）
⑥ 校准          人工盲抽 20–30 条，报 judge 与人的一致率
⑦ 统计          分层准确率 + 配对检验 + 置信区间
⑧ 报告          出 HTML，同时给 CSV 明细供复核
```

第 ⑥ 步不能省。LLM judge 是**会出错的测量仪器**，不是中立法官——有已知的位置偏差、长度偏差、自我偏好。人工抽检是唯一能校准它的手段。

---

## 七、出题的分工

问题集自动生成候选（每个设备、每个故障模式、每条流程套模板），然后**人工审一遍**。

审的重点三条：

1. **答案唯一吗** —— 会不会并列
2. **答案在数据里吗** —— 问的东西真的存在吗
3. **措辞有歧义吗** —— 两种合理解读会不会导致不同答案

自动生成能出量，但审不出这三条的话，测出来的准确率反映的是题目的质量而不是系统的质量。
